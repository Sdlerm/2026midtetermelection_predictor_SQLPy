This file gives Claude Code the context needed to work in this repo without
re-deriving it each session. For full pipeline/setup docs, see `README.md`.

## Project overview

A polling-based forecaster for the 2026 US Senate races. It blends a
credibility- and recency-weighted poll average with a state structural-lean
baseline, a six-indicator FRED economic climate score, and a presidential
approval adjustment into a projected vote share per candidate, then rolls
individual race projections up into a projected Senate seat count.

## Pipeline / how to run

Order matters — each step depends on data written by the previous one:

1. `python init_db.py` — creates `db/elections.db` (idempotent, safe to re-run).
2. `python senate_ingest.py` — loads `data/senate.csv` (polls) plus
   `data/senate_nominees.csv` and `data/state_lean.csv` into the DB.
3. `python fetch_economics.py` — pulls FRED indicators into `climate_factors`
   (needs `FRED_API_KEY` in `.env`).
4. `python senate_model.py` — runs the model, prints projections + Senate
   control to the terminal.
5. `python charts.py` (matplotlib, saves `margins.png`/`vote_shares.png`/
   `seat_count.png`) or `streamlit run dashboard.py` (interactive dashboard).

`export_map_csv.py` is an auxiliary one-off that exports `predict_all_races()`
output to `map_data.csv` for external mapping tools.

## Architecture / key files

- **`init_db.py`** — SQLite schema (`pollsters`, `races`, `candidates`,
  `polls`, `climate_factors`, `historical_results`) and the `get_connection()`
  helper used everywhere else.
- **`senate_model.py`** — the core model. Constants worth knowing:
  `LEAN_ALPHA` (poll vs. lean blend), `LAMBDA` (recency decay), `ECON_WEIGHT`,
  `APPROVAL_WEIGHT`, `TOSSUP_THRESHOLD_PP`, `INDIE_CAUCUS = {"I": "D"}`
  (independent-candidate caucus mapping, e.g. Dan Osborn in NE). Key
  functions: `predict_all_races()`, `project_senate_control()`,
  `weighted_average_and_stderr()`, `lean_baseline()`.
- **`dashboard.py`** — Streamlit UI; predictions are loaded once via a
  `@st.cache_data`-wrapped `load_predictions()`.
- **`charts.py`** — matplotlib chart generation, run standalone.
- **`fetch_economics.py`** / **`senate_ingest.py`** — external data ingestion
  into the DB (see `README.md` for the safeguards `senate_ingest.py` applies:
  question-block dedup, stale-poll filtering, generic-ballot skipping).

## Conventions

- `snake_case` for functions/variables, `UPPER_CASE` for module-level
  constants.
- DB access goes through `get_connection()` / manual `.close()` — no context
  managers are used for SQLite connections in this codebase; follow the
  existing pattern rather than introducing `with` blocks.
- States are always 2-letter abbreviations at the DB layer. Full state names
  only appear when ingesting historical/external CSVs and get mapped to
  abbreviations at that boundary.
- Any code that groups race data by party must not assume only `"D"`/`"R"`
  keys exist — independent candidates use `"I"` (see the Gotchas section).
- No test suite (no `pytest`, no `test_*.py`). Verify changes by running the
  affected script directly (see Pipeline section) and spot-checking output.

## Gotchas / known issues

- **`senate_model2.py`** (repo root, untracked) is a stale, out-of-date
  duplicate of `senate_model.py` from before the poll-stderr work — it is not
  imported by anything. Don't treat it as source of truth or edit it as if it
  were live code; if it's still lying around and unused, it's a candidate for
  deletion rather than a file to keep in sync with `senate_model.py`.
- **Independent candidates**: any function that keys a state's finalists by
  party string (e.g. building a `{"D": ..., "R": ...}` dict) needs an explicit
  fallback for `"I"` — Nebraska (Ricketts-R vs. Osborn-I) has no Democratic
  nominee, so a `D`/`R`-only lookup silently drops that race. `charts.py`'s
  `plot_vote_shares()` and `plot_race_margins()` both handle this; mirror that
  pattern in any new code that does similar grouping.
- **Generated artifacts** — `*.png` charts, `map_data.csv`, and
  `db/elections.db` are gitignored and regenerated by the pipeline; don't hand
  edit them.
- **`.env`** holds `FRED_API_KEY` — gitignored, never print or commit it.
