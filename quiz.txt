F rule: If a pollster is F-rated, it is excluded from the weighted average unless it is the only pollster for that race. The model uses the po.grade column to determine if a pollster is F-rated. If the grade is F, the pollster is excluded from the weighted average calculation. This is implemented in the weighted_average function in senate_model.py, where it checks the po.grade column and excludes F-rated pollsters from the calculation unless they are the only pollster for that race.

(2) The F-exclusion SQL says: WHERE COALESCE(po.grade, '') != 'F'. What would break if you removed COALESCE and wrote po.grade != 'F'?
# If you removed COALESCE, any rows where po.grade is NULL would be excluded from the result,
which could lead to incorrect calculations.
COALESCE ensures that NULL values are treated as empty strings, so they are not excluded unless they are explicitly 'F'.
Yes, NULL is the sneaky one. In SQL, any comparison with NULL returns NULL ("unknown"), not TRUE, and WHERE keeps only TRUE rows. So NULL-grade pollsters would quietly drop out. COALESCE swaps NULL for '' first, and '' != 'F' is TRUE. That's a silent failure, the exact kind your project rules ban.

(3) Why does the model use pollster credibility to weight polls?
The model uses pollster credibility to weight polls because not all pollsters are equally reliable.
Credibility scores reflect the historical accuracy and methodology of each pollster, allowing the model to give more weight to polls from more credible sources. This helps to produce a more accurate and reliable prediction by reducing the influence of less trustworthy polls on the overall result.

Independent errors add in quadrature, like the sides of a right triangle: σ_national and σ_local are the legs, σ_total is the hypotenuse. calibration.py computes this rather than letting you set it by hand, so the three can never disagree.
